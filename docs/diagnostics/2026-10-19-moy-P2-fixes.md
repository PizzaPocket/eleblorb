## 2. Instrumentation overhead and timing names

`city_generator.gd` records detailed stage, activation-frame and release
telemetry only when the probe opts in, and bounds each record array at 8,192
entries. Recursive collision counting is limited to telemetry mode. The probe
stores each sample's frame data in a compact packed-float buffer and writes
JSONL after sampling; it does not keep a dictionary per frame or serialize
between views. The memory summary reports observed and observer-adjusted
static-memory distributions; the adjustment subtracts the exact 104-byte
packed buffer allocation per captured frame.

Request completion (`request_to_loaded_ms`) is recorded separately from time
waiting until the pack is eligible (`loaded_wait_eligibility_ms`). The final
run recorded 588 activation stages: p95 request-to-loaded was 6,263 ms and
p95 loaded-wait-to-eligibility was 1,008 ms. Resource get, instantiate and
`add_child` remain explicitly synchronous timings; `add_child_sync_ms` is not
deferred physics/GPU completion. Release timing is measured to the actual
`tree_exited` callback, not inferred from `queue_free`.

## 3. Request hysteresis and lifetime evidence

Request release radii now exceed activation/request radii (Moy 560 m; hotel
160 m), so an in-flight request remains tracked until it can be safely
consumed or released. The probe records load completion, pending exits,
global class counts, city actor identities and actor subtree paths/classes/
owners/groups/positions.

The final two unload/reload cycles both settled. Node totals were 42,606 before
departure, 18,639 after city unload, and 42,606 after reload. At each unload
settle: active packs 0, requested packs 0, pending exits 0, city actor-group
identities 0. Each equivalent reloaded state had 196 active packs and 13
`city_npcs` (11 resident points plus the two NPC nodes under the shop and city
roots). The second reload's path diff had 782 additions and 782 removals, all
under `WesternCity`; class and group counts matched, so this is the same 11
NPC subtrees being recreated, with no net node growth.

An earlier attempt reported +55 nodes because the harness moved the player to
`(-1600, 0)`, a valid wilderness encounter area. The diff identified that
growth exactly as `/root/Main/SkeletonSpawner/Skeleton` and its 54 descendants
(one `StaticBody3D`, 23 `MeshInstance3D`, 30 `Node3D`, one
`CollisionShape3D`); it was outside `WesternCity`. The unload test now returns
to the protected Crossroads clearing to avoid spawning an unrelated skeleton.
The final run reproduced no +55 growth.

The code-level hysteresis correction is in place, but standing in the hotel
72–140 m annulus, rapid re-entry while loading, multiple controlled bodies,
occupied train supports and held vine-anchor retention have not been exercised
in a player-controlled test. City-wide eligibility still follows the

Runner options used or added:

- `--run-id=<name>` selects unique JSON/JSONL output names.
- `--route=<comma-separated-sample-names>` selects a focused partial route;
